doctor - diagnose settings, key and encryption before starting the WAS

Usage
  java [-D...] -jar {jar} doctor [--config <file>] [--offline] [--lang en|ko]

Options
  --config <file>   External Properties file (optional, same rules as Tomcat).
  --offline         Do not contact Vault or AWS KMS; check only their settings, token, SDK and files (SKIP).
  --lang en|ko      Message language for this run only (optional).

Checks
  JAR built-in settings, JAR history, settings loading (typos and conflicts stop here), external config, -D options
  applied or ignored, algorithm, language, warning policy, key source and key ID, key file existence/type/permission,
  key environment variable presence, Vault token/CA/version pinning, AWS SDK/data key file/region/-D credentials,
  reading the key (length and format), public default key, and an encrypt/decrypt self test with tamper detection.

Output
  [PASS] ...   [WARN] ...   [FAIL] ...   [INFO] ...   [SKIP] ...
         Action: ...  (under WARN/FAIL)
  Result: PASS n, WARN n, FAIL n, SKIP n
  Status codes are the same in every language. Exit code: 0 when there is no FAIL, otherwise 1.
  Exit code 0 is also returned with WARN only (e.g. the public default key), so do not use it as a production
  approval on its own: also check config show (public key or not), fingerprint and a real DB connection.

Examples
  Windows PowerShell
    java -jar .\{jar} doctor
    java "-Dcrypto.key.source=env" -jar .\{jar} doctor
  Linux
    java -Dcrypto.config.file=/etc/java-crypto-kit/vault.properties -jar ./{jar} doctor --offline
    java -jar ./{jar} doctor || echo "fix the FAIL items before starting Tomcat"

Expected result (excerpt)
  [PASS] Settings loaded (JAR + external Properties + JVM -D)
  [PASS] Key read: 32 bytes, valid format, key fingerprint 5b1c...
  [PASS] Encrypt/decrypt self test passed (tampered ciphertext rejected)
  [WARN] The public default key is in use (anyone can decrypt).
         Action: Embed your own key (keygen, then config embed-key) ...

Errors and fixes
  [FAIL] The file of crypto.key.file (...) does not exist  -> check the path and the read permission of the WAS account.
  [FAIL] Vault rejected authentication ...                -> issue a new token (help vault).
  [FAIL] The AWS SDK for Java 2.x ... is not installed     -> install the KMS bundle (help aws-kms).

Note
  doctor PASS does not mean Tomcat starts or the DB connection works. Keys, tokens and plaintext are never printed.

Related: info, config show, fingerprint, help vault, help aws-kms
