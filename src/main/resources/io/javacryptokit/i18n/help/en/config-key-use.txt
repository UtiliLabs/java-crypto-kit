config key use - change the default key of a type (creates a new JAR)

Usage
  java -jar {jar} config key use --key-id <ID>
       --operator <ID> [--type pass|key] [--reason <text>] [--jar <jar>]
       [--out <jar> | --replace] [--yes]
       [--admin-pass-file <file>] [--lang en|ko]

Options
  --key-id <ID>     Registered key ID to make the default (required, type
                    found from the key)
  --type pass|key   Expected type (optional; fails if different)
  --operator <ID>   Operator ID for the history (required)
  --reason <text>   Reason for the history (required, asked interactively)
  --jar <jar>       JAR to change (optional, default: the running JAR)
  --out <jar>       Result JAR (optional, default <name>-cfg.jar)
  --replace         Replace the original (backup first)
  --yes             Skip the CHANGE confirmation (not the reason)
  --admin-pass-file <file>
                    Admin password file (non-interactive, mode 600)
                    Without it the admin password is asked (hidden)
  --lang en|ko      Message language for this run (optional)
  Only the default key of that type changes (crypto.key.active.pass or
  crypto.key.active.key). Existing ciphertext still decrypts (by key ID).

Result
  Created JAR : /opt/app/java-crypto-kit-{version}-cfg.jar
  Changes     : crypto.key.active.pass (pass-default -> p2)
  Default key : pass=p2

Examples
  java -jar {jar} config key use --key-id p2 --operator ops
