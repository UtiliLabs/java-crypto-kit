rekey - re-encrypt a ciphertext with another key (new key ID, no plaintext)

Usage
  java [-D...] -jar {jar} rekey
       [--type pass|key] [--key-id <ID>]
       [--from-config <file> | --from-jar <jar>]
       [--to-config <file> | --to-jar <jar>]
       [--value <ciphertext>] [--admin-pass-file <file>] [--lang en|ko]

Options (give at least one; the other side uses the current settings)
  --type pass|key        Target key type (optional; default: same type as the
                         existing ciphertext)
  --key-id <ID>          Target key ID (optional, type found from the key).
                         With only --type/--key-id it moves to another key of
                         the same settings (also across types).
  --from-config <file>   Old settings = running JAR values + this Properties
  --from-jar <jar>       Old settings = built-in values of that JAR (e.g. the
                         JAR before the key change)
  --to-config <file>     New settings = running JAR values + this Properties
  --to-jar <jar>         New settings = built-in values of that JAR
  --value <ciphertext>   Ciphertext to re-encrypt (optional, else hidden input)
  --admin-pass-file <file>
                         Admin password file (non-interactive, mode 600)
                         Without it the admin password is asked (hidden)
  --lang en|ko           Message language for this run (optional)

Result
  ENC[v1:key02:...]      (only the new ciphertext, one line on standard output)
  The old key is found by the key ID of the ciphertext; the result is printed
  only after it decrypts with the target key. Same key ID or same key: refused.
  If the target key is a public default key, standard error gets one warning.

Examples (new.jar: a JAR with the new key, made by config embed-key)
  java -jar {jar} rekey --to-jar new.jar
  java -jar {jar} rekey --key-id app-pass
