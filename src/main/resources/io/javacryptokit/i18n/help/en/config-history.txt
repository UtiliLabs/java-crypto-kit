config history - change history of the JAR built-in settings (admin)

Usage
  java -jar {jar} config history
       [--type pass|key | --all] [--jar <jar>]
       [--admin-pass-file <file>] [--lang en|ko]

Options
  --type pass|key   Only changes about keys of that type (default pass)
  --all             The whole history (both types, other settings, admin)
  --jar <jar>       JAR to read (optional, default: the running JAR)
  --admin-pass-file <file>
                    Admin password file (non-interactive, mode 600)
                    Without it the admin password is asked (hidden)
  --lang en|ko      Message language for this run (optional)
  --type and --all cannot be used together. The whole history is verified
  before it is filtered, and entries keep their original numbers.

Result (part, --type key)
  History check: OK (3 changes, hash chain and current settings match)
  Showing      : key-related 1 of 3 changes

  #1  2026-11-22T05:30:12Z  operator ops  config embed-key  [key]
      reason: rotate the production key
      crypto.key.id: default -> key01
      key key01: (none) -> key, embedded, crypto.key.*, file
        Fingerprint:
          ab12cd34...(all 64)
  Only successful changes are recorded; management info (full fingerprint,
  KDF, rounds, salt, operator, reason) is shown unmasked. Key values and the
  admin password are never in the history. Items an older format did not
  record show (not recorded). Admin password setup/changes appear only with
  --all, tagged [admin]. A damaged history or one that does not match the
  settings gives [reason: INTEGRITY] and exit code 1.

Examples
  java -jar {jar} config history
  java -jar {jar} config history --type key --jar new.jar
  java -jar {jar} config history --all
