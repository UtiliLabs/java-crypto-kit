config embed-key - build a crypto.key.* AES key and a new key ID into a new JAR

Usage
  java -jar {jar} config embed-key --from-file <key file>
       --key-id <new key ID> --operator <ID> [--source embedded]
       [--reason <text>] [--jar <jar>] [--out <jar> | --replace]
       [--yes] [--admin-pass-file <file>] [--lang en|ko]

Options
  --from-file <key file>   Key file in keygen format (required, no raw key)
  --key-id <new key ID>    New key ID (required, 1-64 letters, digits, _ or -).
                           Registered and public default key IDs cannot be
                           used; an ID used in the history only to restore the
                           same key (matching full fingerprint).
  --operator <ID>          Operator ID for the history (required)
  --source embedded        Needed only when the target JAR's crypto.key.source
                           is not embedded (switches it). Omit it otherwise.
  --reason <text>          Reason for the history (required, asked
                           interactively)
  --jar <jar>              JAR to change (optional, default: the running JAR)
  --out <jar>              Result JAR (optional, default <name>-cfg.jar)
                           An existing file is never overwritten.
  --replace                Replace the original (backup first)
  --yes                    Skip the CHANGE confirmation (not the reason)
  --admin-pass-file <file> Admin password file (non-interactive, mode 600)
                           Without it the admin password is asked (hidden)
  --lang en|ko             Message language for this run (optional)
  The previous AES key stays in the key list with its key ID, so existing
  ciphertext still decrypts (an external key that cannot be read now is not
  kept; this is shown). Pass keys and other keys are unchanged.
  Adding and rotating keys: help config key

Result
  Created JAR : C:\work\java-crypto-kit-{version}-cfg.jar
  Changes     : crypto.key.embedded (secret)
                crypto.key.id (default -> key01)
                crypto.keys.default.type ((none) -> key)
                ...
  Fingerprint : ab12cd34ef56...7890abcd

Examples
  java -jar {jar} config embed-key --from-file example.key --key-id key01 --operator ops
  java -jar {editedJar} fingerprint --type key
