rekey - 기존 암호문을 이전 키에서 새 키로 재암호화(평문은 표시하지 않음)

사용 형식
  java [-D...] -jar {jar} rekey [--from-config <파일> | --from-jar <jar>] [--to-config <파일> | --to-jar <jar>]
                                [--value <암호문>] [--lang en|ko]

옵션(이전 쪽 = from, 신규 쪽 = to, 하나 이상 지정)
  --from-config <파일>   이전 설정 = 실행 중인 JAR의 내장 값 + 이 Properties 파일만.
  --from-jar <jar>       이전 설정 = 그 JAR의 내장 값만(예: embed-key 하기 전의 원본 JAR).
  --to-config <파일>     신규 설정 = 실행 중인 JAR의 내장 값 + 이 Properties 파일만.
  --to-jar <jar>         신규 설정 = 그 JAR의 내장 값만.
                         지정하지 않은 쪽은 현재 실행 설정(info에 보이는 설정)을 씁니다.
                         -D 옵션과 CRYPTO_CONFIG_FILE은 그 현재 실행 설정 쪽에만 적용됩니다.
  --value <암호문>       재암호화할 암호문(선택). 없으면 터미널에서 표시하지 않고 입력받습니다.
  --lang en|ko           이번 실행의 메시지 언어(선택).
  양쪽 모두 구현된 모든 키 공급원을 쓸 수 있습니다: embedded, file, env, vault, aws-kms.

동작
  두 설정의 키ID와 키(지문)가 서로 다른지 확인하고, 이전 키로 복호화(GCM 태그 검증)한 뒤 새 키·키ID와 새 IV로
  암호화하고, 결과를 새 키로 다시 복호화해 검증하며, 이전 키로는 복호화되지 않는지 확인합니다. 표준 출력에는 새 암호문만,
  요약은 표준 오류에 씁니다. 기존 암호문은 바꾸거나 지우지 않습니다.

키 교체 절차
  1) 새 키 만들기:          java -jar {jar} keygen --out rotated-key.key
  2) 새 JAR 만들기:         java -jar {jar} config embed-key --from-file rotated-key.key --key-id prod02 --operator <ID>
  3) 값마다 재암호화:       java -jar java-crypto-kit-{version}-configured.jar rekey --from-jar java-crypto-kit-{version}.jar
  4) 각 JNDI Resource의 password="..."를 새 암호문으로 바꾸고 새 JAR를 배포한 뒤 WAS를 재시작합니다.
  5) 모든 암호문을 바꾸고 verify로 확인할 때까지 이전 키(또는 이전 JAR)를 보관합니다.
  이전 키를 이미 잃었다면(예: 내장 키를 바꾼 뒤 원본 JAR를 지움) 기존 암호문은 재암호화할 수 없습니다.
  이 경우 DB 비밀번호 평문으로 다시 encrypt합니다.

예제
  Windows PowerShell
    java -jar .\java-crypto-kit-{version}-configured.jar rekey --from-jar .\java-crypto-kit-{version}.jar
    $new = java -jar .\{jar} rekey --from-config C:/secure/old.properties --to-config C:/secure/new.properties --value "ENC[v1:prod01:...]"
  Linux
    java -jar ./{jar} rekey --from-config /etc/java-crypto-kit/old.properties --to-config /etc/java-crypto-kit/vault.properties
    java -jar ./{jar} rekey --from-jar ./old/{jar} --to-jar ./new/{jar} --value 'ENC[v1:default:...]' > new-password.txt

예상 결과
  표준 출력: ENC[v1:prod02:...]
  표준 오류: 이전: 키ID prod01, 키 지문 ... / 신규: 키ID prod02, 키 지문 ...
             [PASS] 신규 키로 복호화 확인, 새 IV로 암호화, 이전 키로는 복호화되지 않음

대표 오류와 해결
  [사유: USAGE] 키ID가 같음 / 같은 키      -> 신규 쪽에는 새 키와 새 키ID가 필요합니다.
  [사유: USAGE] 양쪽 모두 현재 실행 설정   -> --from-... 또는 --to-...를 지정하세요.
  [사유: KEY_ID_MISMATCH] -> 이전 설정으로 만든 암호문이 아닙니다. 이전 설정을 확인하세요.
  [사유: INTEGRITY]       -> 이전 키가 이 암호문을 만든 키가 아닙니다.

보안 주의
  평문은 메모리에서만 쓰고 사용 후 지웁니다. --value는 평문이 아닌 암호문이지만 셸 기록에 남으므로 화면 비표시 입력을
  권장합니다. 새 암호문도 이전 암호문과 같은 수준으로 관리하세요.

관련 명령: config embed-key, fingerprint, verify, kms datakey
