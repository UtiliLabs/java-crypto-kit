help aws-kms - AWS KMS Envelope Encryption을 키 공급원으로 사용(crypto.key.source=aws-kms)

동작 구조
  KMS 마스터 키(KMS 밖으로 나오지 않음) =(보호)=> AES-256 데이터 키 => java-crypto-kit AES-GCM => 암호문
  1) 한 번: kms datakey가 KMS에 데이터 키를 요청(GenerateDataKey AES_256)하거나 기존 키를 감싸고(Encrypt),
     암호화된 데이터 키(CiphertextBlob)만 파일에 보관합니다.
  2) WAS 시작마다: KMS Decrypt로 그 파일에서 같은 데이터 키를 복원합니다. 시작할 때 새 데이터 키를 만들지 않습니다
     (만들면 기존 암호문을 복호화할 수 없음).
  Encryption Context java-crypto-kit:key-id=<crypto.key.id>를 항상 함께 보내 데이터 키를 키ID에 묶습니다.

1) 선택 설치 AWS SDK 묶음(aws-kms에만 필요, 기본 JAR는 필요 없음)
  java-crypto-kit-aws-kms-lib-{version}.zip을 내려받습니다(또는 직접 빌드: gradlew build -> build/distributions).
  AWS SDK for Java 2.x(kms, sts, url-connection-client와 의존 JAR, Apache-2.0)가 들어 있습니다.
  Tomcat: aws-kms-lib/*.jar를 {jar}와 같은 CATALINA_BASE/lib에 풉니다.
  CLI   : Windows  java -cp "{jar};aws-kms-lib/*" io.javacryptokit.cli.CryptoCli <명령>
          Linux    java -cp "{jar}:aws-kms-lib/*" io.javacryptokit.cli.CryptoCli <명령>
  java -jar는 -cp를 무시하므로 KMS가 필요한 명령(kms datakey, doctor, rekey, encrypt)은 -cp 형식을 씁니다.

2) 권한(최소 권한)
  WAS: KMS 키에 kms:Decrypt.  데이터 키 생성: kms:GenerateDataKey 또는 kms:Encrypt(+ kms:Decrypt).
  자격증명은 AWS SDK 표준 체계에서 가져옵니다: 환경변수, 웹 ID(EKS IRSA), 프로필, 컨테이너 자격증명
  (ECS, EKS Pod Identity), EC2 인스턴스 프로필. Access Key를 Properties·-D에 두지 마세요.

3) 데이터 키 파일 만들기
  java -cp "{jar}:aws-kms-lib/*" io.javacryptokit.cli.CryptoCli kms datakey --out /etc/java-crypto-kit/prod.datakey --config /etc/java-crypto-kit/kms.properties
  기존 암호문을 유지하려면 --from-file <현재 키 파일>을 더합니다(같은 키, 같은 키ID).

4) 설정
  crypto.key.source=aws-kms
  crypto.key.id=prod01
  crypto.aws.region=ap-northeast-2            (비우면 AWS_REGION 또는 SDK 기본 리전 체계)
  crypto.aws.kms.key.id=alias/java-crypto-kit-prod
  crypto.aws.kms.data-key.file=/etc/java-crypto-kit/prod.datakey
  crypto.aws.kms.timeout.ms=10000
  엔드포인트(VPC 엔드포인트, FIPS, 에뮬레이터): AWS SDK 표준 변수 AWS_ENDPOINT_URL_KMS=https://...

5) 확인
  java -cp "{jar}:aws-kms-lib/*" io.javacryptokit.cli.CryptoCli doctor --offline    (SDK, 파일, 리전, 네트워크 없음)
  java -cp "{jar}:aws-kms-lib/*" io.javacryptokit.cli.CryptoCli doctor              (KMS Decrypt와 자체 검증까지)

장애와 복구
  - AccessDeniedException: IAM·키 정책. IncorrectKeyException: 데이터 키가 다른 KMS 키 소속.
    InvalidCiphertextException: 데이터 키 파일 손상 또는 crypto.key.id가 다름. NotFoundException: 키·리전이 틀림.
    자격증명·리전 없음, 시간 초과, 네트워크: doctor 메시지를 확인하세요.
  - 실패하면 DataSource 생성이 중단되고 다른 키로 바꾸지 않습니다. KMS 호출 1회의 전체 시간은
    crypto.aws.kms.timeout.ms(SDK 표준 재시도 포함)로 제한됩니다. 원인을 고친 뒤 WAS를 재시작하세요.
  - 데이터 키 파일과 KMS 키를 보관하세요. 둘 중 하나를 잃거나 KMS 키를 삭제하면 암호문을 잃습니다.
  - AWS SDK 자체 메시지는 번역하지 않으며, SDK 오류 메시지는 출력하지 않습니다(오류 코드만).

관련 명령: kms datakey --help, doctor, rekey, fingerprint
