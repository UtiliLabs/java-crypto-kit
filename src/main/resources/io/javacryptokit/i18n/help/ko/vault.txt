help vault - HashiCorp Vault KV 버전 2를 키 공급원으로 사용(crypto.key.source=vault)

개요
  AES-256 키(Base64, keygen 형식)를 Vault KV v2 Secret의 필드에 저장합니다. 시작할 때
  GET <crypto.vault.url>/v1/<crypto.vault.mount>/data/<crypto.vault.path>[?version=<crypto.vault.ver>]를
  X-Vault-Token 헤더로 읽어 crypto.vault.field 필드를 키로 씁니다. JDK 표준 HTTPS만 쓰므로 추가 JAR가 없습니다.
  Vault Transit(Vault 안에서 암복호화)은 별개 기능이며 지원하지 않습니다.

1) Vault 준비(vault CLI 예)
  vault secrets enable -path=secret kv-v2                      (아직 없으면)
  java -jar {jar} keygen --out prod02.key
  vault kv put secret/java-crypto-kit/prod key=@prod02.key     (출력된 버전 번호를 기록, 예: 1)
  읽기만 허용하는 정책(최소 권한):
    path "secret/data/java-crypto-kit/prod" { capabilities = ["read"] }
  그 정책으로 WAS용 토큰을 발급합니다(또는 Vault Agent와 토큰 파일 사용).

2) 설정(config set으로 JAR 내장, 또는 외부 Properties)
  crypto.key.source=vault
  crypto.key.id=prod02
  crypto.vault.url=https://vault.example.internal:8200
  crypto.vault.mount=secret
  crypto.vault.path=java-crypto-kit/prod
  crypto.vault.field=key
  crypto.vault.ver=1
  crypto.vault.token.file=/run/secrets/vault-token      (또는 비우고 crypto.vault.token.env=VAULT_TOKEN 사용)
  crypto.vault.ca.file=/etc/java-crypto-kit/vault-ca.pem  (사설 CA, 비우면 JVM 신뢰 저장소)
  crypto.vault.timeout.ms=5000
  java -jar {jar} config set crypto.key.source=vault crypto.key.id=prod02 crypto.vault.url=https://vault.example.internal:8200 crypto.vault.path=java-crypto-kit/prod crypto.vault.ver=1 crypto.vault.token.file=/run/secrets/vault-token --operator example-admin --yes

3) 토큰 공급(Properties·-D·JAR에는 절대 두지 않음)
  Linux  : export VAULT_TOKEN=...  (또는 systemd Environment=, 또는 WAS 계정만 읽는 토큰 파일)
  Windows: 서비스 계정에 setx VAULT_TOKEN ..., 또는 ACL을 제한한 토큰 파일.

4) 확인
  java -jar {jar} doctor --offline      설정, 토큰 존재, CA 파일, 버전 고정(네트워크 없음)
  java -jar {jar} doctor                연결·인증·키 조회·자체 검증까지
  java -jar {jar} fingerprint           다음과 비교: java -jar {jar} fingerprint --key-file prod02.key

동작과 장애
  - TLS 인증서와 호스트 이름은 항상 검증하고, 리다이렉트는 따르지 않습니다(토큰이 다른 서버로 가지 않게).
  - 시도마다 연결과 응답을 각각 최대 crypto.vault.timeout.ms까지 기다립니다. 연결 실패, 시간 초과,
    HTTP 429/500/502/503/504만 최대 3회(0.5초, 1초 대기) 시도합니다. TLS·인증·권한·Secret 없음은 바로 실패합니다.
  - 403이면 auth/token/lookup-self로 확인해 "인증 거부"(토큰 만료·폐기)와 "권한 부족"(정책)을 구분합니다.
    Vault는 정책 밖의 경로를 "없음"이 아니라 "권한 부족"으로 답하므로, 권한 부족이면 마운트·경로 오타도 확인하세요.
    404는 정책 안의 경로에 Secret이나 버전이 없음(또는 KV v2 마운트가 아님)입니다.
  - 실패하면 DataSource 생성이 중단되고 Tomcat 로그에 [java-crypto-kit] [사유: KEY_SOURCE] ...가 남습니다.
    내장 키로 바꾸지 않습니다. 원인을 고친 뒤 WAS(또는 애플리케이션)를 다시 시작하세요.
  - 키는 DataSource를 만들 때 한 번 읽습니다(JDBC 연결마다 읽지 않음). 나중에 토큰이 만료되어도 실행 중인 Pool은
    계속 동작하지만 다음 재시작에는 유효한 토큰이 필요합니다.
  - crypto.vault.ver를 고정하세요. 최신을 읽으면 새 버전이 쓰였을 때 다음 재시작부터 키가 바뀝니다.
    키 교체: 새 키를 새 키ID와 함께 새 버전으로 쓰고, rekey로 암호문을 다시 암호화한 뒤
    (rekey --from-config old.properties --to-config new.properties) crypto.vault.ver와 crypto.key.id를 바꿉니다.

관련 명령: doctor, fingerprint, rekey, config help
