config set - JAR 내장 설정을 영구 변경(소스 수정·Gradle 재빌드·외부 Properties 불필요)

사용 형식
  java -jar {jar} config set <이름>=<값> [<이름>=<값> ...] --operator <ID>
                  [--reason <사유>] [--jar <jar>] [--out <jar> | --replace] [--yes] [--lang en|ko]

옵션
  <이름>=<값>        바꿀 설정(하나 이상). 이름·기본값·허용값은 config help에서 확인합니다.
                     crypto.key.embedded는 여기서 바꿀 수 없습니다(키 파일을 쓰는 config embed-key 사용).
  --operator <ID>    이력에 남길 수정자 ID(필수). 문자·숫자·. _ @ -, 1~64자.
                     기록용이며 본인 인증이 아닙니다(관리자 비밀번호 없음, 파일 권한으로 접근을 통제).
  --reason <사유>    이력에 남길 변경 사유(선택, 한 줄, 200자 이하).
  --jar <jar>        바꿀 JAR(선택). 기본값: 실행 중인 JAR.
  --out <jar>        결과 JAR(선택). 기본값: 원본 옆의 <이름>-configured.jar, 이미 바꾼 JAR면 다음 순번
                     (x-configured.jar -> x-configured-2.jar -> -3 ...). 같은 이름의 파일이 있으면 덮어쓰지 않고
                     멈춘 뒤 쓸 수 있는 --out 이름을 안내합니다.
  --replace          새 JAR 대신 원본 JAR를 교체(먼저 <이름>.bak-<UTC 시각> 백업, 원자적 이동).
                     실행 중인 JAR에는 쓸 수 없고 --out과 함께 쓸 수 없습니다.
  --yes              키 관련 설정의 CHANGE 확인 입력을 생략(무인 자동화용).
  --lang en|ko       이번 실행의 메시지 언어(선택).

동작
  지정한 설정 줄만 바꾸고(주석 유지), 바꾼 뒤 전체 조합을 실행 때와 같은 규칙으로 재검증하고, 변경 이력에 1건
  (시각, 수정자, 설정, 이전 -> 변경 값)을 더합니다. 임시 JAR를 쓰고 다시 읽어 검증(ZIP/CRC, Manifest, Main-Class, 항목,
  설정, 이력)한 뒤에만 제자리로 옮깁니다. 실패하면 원본 JAR와 이력은 그대로입니다. 서명된 JAR와 이력이 손상된 JAR는
  거부합니다. 키 관련 설정(키 공급 방식, 키ID, Vault·KMS 키 위치)을 바꾸면 기존 암호문 영향을 보여 주고 터미널에서
  CHANGE 입력 또는 --yes가 필요합니다.

예제
  Windows PowerShell
    java -jar .\{jar} config set crypto.lang=en --operator example-admin
    java -jar .\{jar} config set crypto.warning.enabled=false crypto.output.encoding=base64 --operator example-admin --reason "설정 변경"
    java -jar .\tools\{jar} config set crypto.lang=ko --jar C:/tomcat/lib/{jar} --replace --operator example-admin
  Linux
    java -jar ./{jar} config set crypto.key.source=file crypto.key.file=/etc/java-crypto-kit/app.key --operator example-admin --yes
    java -jar ./{jar} config set crypto.key.source=vault crypto.vault.url=https://vault.example.internal:8200 crypto.vault.path=java-crypto-kit/prod crypto.vault.ver=3 --operator example-admin --yes
    java -jar ./{jar} config set crypto.jvm.override.enabled=false --out ./dist/{jar} --operator example-admin

예상 결과
  [완료] JAR 내부 설정을 바꾼 새 JAR를 만들었습니다(원본은 바뀌지 않음).
    원본 JAR(변경 안 됨): /opt/app/{jar}
    결과 JAR(변경 결과) : /opt/app/java-crypto-kit-{version}-configured.jar
    변경 항목: crypto.lang (ko -> en)
    변경 이력: 1번째 변경, 2026-11-21T05:30:12Z (UTC), 수정자 example-admin
  --replace면 대상·백업 파일과 복구 명령(mv / Move-Item)을 출력합니다.
  확인: config show, config history. 새 JAR로 WAS를 재시작하면 적용됩니다.

대표 오류와 해결
  [사유: CONFIGURATION] 지원하지 않는 설정 항목 '...'. '...'을(를) 의도했는지 확인 -> config help로 이름 확인.
  [사유: CONFIGURATION] 변경 후 JAR 내부 설정이 올바르지 않습니다 -> 값을 고치세요. 아무것도 바뀌지 않았습니다.
  [사유: USAGE] 수정자 ID가 없습니다                 -> --operator <ID>를 추가하세요.
  [사유: USAGE] 바꿀 내용이 없습니다                 -> 이미 같은 값입니다(이력에 남지 않음).
  [사유: USAGE] 결과 JAR 파일이 이미 있습니다        -> 다른 --out을 지정하거나 파일을 옮기세요.
  [사유: USAGE] 실행 중인 JAR 자신은 교체하지 않습니다 -> JAR 사본으로 실행해 --jar ... --replace를 쓰세요.
  [사유: IO_ERROR] 사용 중이거나 쓰기 권한 없음      -> Tomcat을 멈추고 권한을 확인하거나 새 JAR를 만드세요.
  [사유: INTEGRITY] 이력 손상                        -> 공식 배포 JAR에서 다시 시작하세요.

보안 주의
  JAR에는 사용자 지정 키가 들어갈 수 있으니 읽기·변경 권한을 제한하세요. 실행 시에는 -D와 외부 Properties가 여전히 더
  우선합니다(info에 출처 표시). 설정은 WAS 시작 때 읽으므로 배포 후 재시작하세요.

관련 명령: config help, config show, config history, config embed-key, info
