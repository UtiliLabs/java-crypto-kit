kms datakey - aws-kms 키 공급원용 데이터 키 파일 생성(AWS SDK 선택 묶음 필요)

사용법(java -jar 대신 -cp로 SDK 묶음을 함께 지정)
  java -cp <클래스패스> io.javacryptokit.cli.CryptoCli kms datakey
       --out <파일> [--from-file <키 파일>] [--config <파일>]
       [--reason <사유>] [--operator <ID>]
       [--admin-pass-file <파일>] [--lang en|ko]

클래스패스 CP(JAR와 aws-kms-lib 폴더가 현재 폴더에 있을 때)
  PowerShell: $CP = "{jar};aws-kms-lib/*"
  Linux     : CP="{jar}:aws-kms-lib/*"
  설정 방법·--from-file 예제: docs/user-guide.md 2.17절

옵션
  --out <파일>            만들 데이터 키 파일(필수, 덮어쓰지 않음, POSIX 600)
  --from-file <키 파일>   기존 키(keygen 형식)를 KMS로 감쌉니다.
                          키·키 ID가 그대로라 기존 암호문을 계속 씁니다.
                          없으면 KMS GenerateDataKey로 새 데이터 키를 만듭니다.
  --config <파일>         외부 Properties(아래 설정, JAR·-D에 있으면 선택):
                          crypto.key.source=aws-kms, crypto.aws.kms.key.id,
                          crypto.aws.region, crypto.key.id
  --reason <사유>         생성 사유(필수). 없으면 대화형 터미널에서 묻고,
                          비대화형이면 KMS를 부르기 전에 오류로 멈춥니다.
  --operator <ID>         작업자 ID(선택, 결과에만 표시)
  --admin-pass-file <파일>
                          관리자 비밀번호 파일(비대화형 인증, 한 줄, 권한 600)
                          없으면 관리자 비밀번호를 숨김 입력으로 묻습니다
  --lang en|ko            이번 실행의 메시지 언어(선택)
  crypto.key.* AES 키용입니다. pass 키·추가 키는 config key add
  --source aws-kms로 만듭니다(help config key add). 데이터 키 원문은
  보여 주지 않습니다(KMS로 보호한 파일만 남음). JAR를 바꾸지 않으므로
  사유·작업자를 어떤 이력에도 저장하지 않습니다.

결과
  파일      : /etc/java-crypto-kit/prod.datakey
  방식      : 새 데이터 키(KMS GenerateDataKey)
  키 ID     : key01
  키 지문   : 9d2e...(64자)
  사유      : 운영 데이터 키 준비
  이력      : 저장 안 함(JAR를 바꾸지 않는 명령이라 config history에 없음)
  이 경로를 crypto.aws.kms.data-key.file에 지정합니다(help aws-kms).

예제
  java -cp "$CP" io.javacryptokit.cli.CryptoCli kms datakey --out prod.datakey
