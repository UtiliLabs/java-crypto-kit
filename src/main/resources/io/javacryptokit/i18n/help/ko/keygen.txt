keygen - 새 AES-256 난수 키 파일 생성

사용 형식
  java -jar {jar} keygen --out <키 파일> [--lang en|ko]

옵션
  --out <키 파일>   만들 키 파일(필수). 상위 폴더가 있어야 합니다. 기존 파일은 절대 덮어쓰지 않습니다
                    (키를 잃으면 그 키의 암호문을 복호화할 수 없음).
  --lang en|ko      이번 실행의 메시지 언어(선택).

동작
  SecureRandom으로 32바이트 난수를 만들어 표준 Base64 한 줄(44자)로 씁니다. Linux/macOS에서는 권한 600으로 만듭니다.
  키는 출력하지 않고 키 지문만 보여 줍니다. keygen은 설정·키를 읽지 않습니다.

예제(상위 폴더를 먼저 만듭니다)
  Windows PowerShell(사용자 프로필 아래 폴더: 기본으로 본인·관리자만 접근)
    New-Item -ItemType Directory -Force -Path "$HOME\jck-secure" | Out-Null
    java -jar .\{jar} keygen --out "$HOME\jck-secure\example.key"
    icacls "$HOME\jck-secure\example.key" /inheritance:r /grant:r "${env:USERNAME}:(R)"
    C:\ 바로 아래에 만든 폴더(예: C:\secure)는 기본 상속으로 다른 로컬 사용자도 읽을 수 있으므로
    icacls로 상속을 끊고 필요한 계정(운영자, Tomcat 서비스 계정)만 허용합니다.
  Linux(키 내장용, 본인 폴더)
    mkdir -p -m 700 ~/jck-secure
    java -jar ./{jar} keygen --out ~/jck-secure/example.key
  Linux 서버(파일 키로 사용, Tomcat 실행 계정이 읽음 - root로 실행, 계정 이름은 환경에 맞게)
    install -d -m 750 -g tomcat /etc/java-crypto-kit
    java -jar ./{jar} keygen --out /etc/java-crypto-kit/example.key
    chown tomcat:tomcat /etc/java-crypto-kit/example.key

예상 결과
  키 파일이 생성됐습니다. 키 지문: 3f9a...
  다음: config embed-key --from-file example.key --key-id <새 키ID> --operator <ID>로 키 내장 JAR를 만들거나, ...

다음 단계
  - JAR에 내장:      java -jar {jar} config embed-key --from-file example.key --key-id prod01 --operator <ID>
  - 파일 키로 사용:  crypto.key.source=file, crypto.key.file=/etc/java-crypto-kit/example.key
  - Vault KV v2에 저장(help vault)하거나 AWS KMS로 감싸기(kms datakey --help).

대표 오류와 해결
  [사유: USAGE] 키 파일이 이미 있습니다(FileAlreadyExistsException) -> 다른 이름을 지정하세요.
  [사유: USAGE] 키 파일을 만들 폴더가 없습니다                       -> 폴더를 먼저 만드세요.

보안 주의
  사용 중인 모든 키는 보호된 백업을 두세요. 키 파일을 커밋하거나 메일·메신저로 보내지 마세요.

관련 명령: config embed-key, fingerprint, rekey
