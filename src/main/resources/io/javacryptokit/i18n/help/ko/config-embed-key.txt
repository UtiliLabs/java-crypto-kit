config embed-key - 사용자 지정 AES-256 키와 새 키ID를 JAR에 내장(CLI만으로, 재빌드 없음)

사용 형식
  java -jar {jar} config embed-key --from-file <키 파일> --key-id <새 키ID> --operator <ID>
                  [--source embedded] [--reason <사유>] [--jar <jar>] [--out <jar> | --replace] [--yes] [--lang en|ko]

옵션
  --from-file <키 파일>   keygen으로 만든 키 파일(필수). 키 원문은 인자로 받지 않습니다.
  --key-id <새 키ID>      새 키ID(필수): 영문·숫자·_·-, 1~64자, 예: prod01.
                          JAR의 현재 키ID와 변경 이력에서 쓰인 적 있는 키ID는 거부합니다(이전 키의 암호문과
                          구분되도록). 예전 키로 되돌릴 때는 그때의 JAR(또는 .bak 백업)를 다시 배포합니다.
  --operator <ID>         이력에 남길 수정자 ID(필수, 본인 인증 아님).
  --source embedded       대상 JAR의 crypto.key.source가 embedded가 아닐 때만 필요: embedded로 바꾸면서 키를 내장합니다.
                          이미 embedded(기본값)이면 생략해도 키 내장이 진행됩니다. embedded가 아닌데 생략하면
                          오류로 멈추고 JAR는 바뀌지 않습니다.
  --reason <사유>         이력에 남길 사유(선택).
  --jar <jar>             바꿀 JAR(선택, 기본: 실행 중인 JAR).
  --out <jar>             결과 JAR(선택, 기본 <이름>-configured.jar, 이미 바꾼 JAR면 다음 순번 -configured-2.jar).
                          덮어쓰지 않습니다.
  --replace               백업 후 원본 JAR 교체(실행 중인 JAR 불가, --out과 함께 불가).
  --yes                   CHANGE 확인 입력 생략(무인 자동화).
  --lang en|ko            이번 실행의 메시지 언어(선택).

사용자 지정 키 적용 절차(공개 JAR -> 키 내장 JAR)
  1) java -jar {jar} keygen --out example.key   # 새 키가 필요할 때만(이미 키 파일이 있으면 2)부터)
  2) java -jar {jar} config embed-key --from-file example.key --key-id prod01 --operator example-admin
  3) java -jar java-crypto-kit-{version}-configured.jar config show      (키: 교체된 키, 키 지문)
     java -jar java-crypto-kit-{version}-configured.jar config history   (crypto.key.embedded: (비공개) -> (교체됨))
     java -jar java-crypto-kit-{version}-configured.jar fingerprint --key-file example.key   (같은 지문인지 확인)
  4) 이전 키로 만든 기존 암호문 재암호화:
     java -jar java-crypto-kit-{version}-configured.jar rekey --from-jar java-crypto-kit-{version}.jar
     또는 새 JAR로 DB 비밀번호를 다시 encrypt합니다.
  5) JNDI Resource의 password="..."를 바꾸고, 새 JAR를 CATALINA_BASE/lib에 넣고(이전 JAR 제거) 재시작합니다.
  6) example.key와 키 내장 JAR를 안전하게 보관합니다(둘 다 잃으면 암호문을 복구할 수 없음).

동작
  키 파일을 검증하고(Base64, 정확히 32바이트, 공개 키 아님, 현재 키와 다름), 기존 암호문 영향을 보여 준 뒤 CHANGE
  입력(또는 --yes)을 받아 crypto.key.embedded·crypto.key.id(--source면 crypto.key.source=embedded)를 새 JAR에 쓰고,
  새 키로 실제 암복호화를 확인하며, 키 값 없이 변경 이력에 기록합니다.

예제
  Windows PowerShell
    java -jar .\{jar} config embed-key --from-file "$HOME\jck-secure\example.key" --key-id prod01 --operator example-admin
  Linux
    java -jar ./{jar} config embed-key --from-file /secure/example.key --key-id prod01 --operator example-admin --reason "initial user-provided key" --yes
    java -jar ./{jar} config embed-key --from-file ./new.key --key-id prod02 --source embedded --jar ./app/{jar} --out ./dist/{jar} --operator example-admin

예상 결과
  [주의] JAR 내장 키를 교체합니다(키 파일: example.key). 키ID default -> prod01, ...
  [완료] JAR 내부 설정을 바꾼 새 JAR를 만들었습니다(원본은 바뀌지 않음).
  다음 단계: 1) 처음 적용이면 encrypt(이전 키의 암호문이 있으면 rekey) 2) JNDI password 교체 3) JAR 교체 후 Tomcat 재시작

대표 오류와 해결
  [사유: USAGE] 키ID 충돌                          -> 한 번도 쓰지 않은 새 --key-id를 쓰세요(config history로 확인).
  [사유: USAGE] 공개 기본 키는 내장할 수 없습니다  -> keygen으로 새 키를 만드세요.
  [사유: USAGE] 지금 JAR의 기본 키 공급 방식은 ...  -> --source embedded를 추가하세요.
  [사유: KEY_SOURCE] AES-256 키는 정확히 32바이트여야 합니다 -> keygen으로 만든 키 파일을 쓰세요.

보안 주의
  - 공개 배포 JAR의 기본 키는 공개 키입니다. 운영에 절대 쓰지 마세요.
  - 내장 키는 JAR에서 추출할 수 있습니다. 키 내장 JAR는 GitHub·공개 저장소에 올리지 말고 읽기 권한을 제한하세요
    (chmod 640). 더 강한 분리가 필요하면 file/env 키, Vault, AWS KMS를 쓰세요.

관련 명령: keygen, rekey, fingerprint, config show, config history
